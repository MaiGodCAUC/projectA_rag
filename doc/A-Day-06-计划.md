# A-Day 6：RAG 生成引擎

## 核心目标

实现完整 RAG 问答链路——检索结果 → Prompt 组装 → LLM 生成 → 引用溯源，
支持流式输出（SSE）和多轮对话。

---

## 学习内容

| 知识点 | 说明 |
|--------|------|
| RAG Prompt 设计 | 角色设定 + 业务规则 + 引用格式约束 |
| 上下文窗口管理 | Token 超限时智能截断策略 |
| 条款级引用溯源 | `[来源: 文档名 第X条]` 标记格式 |
| SSE 流式输出 | Server-Sent Events, 逐 token 推送 |
| 多轮对话记忆 | RunnableWithMessageHistory, 对话历史管理 |
| LangSmith Tracing | 全链路可观测（Day 9 预埋） |

## 代码任务

### 1. `rag/generator.py` —— RAG 生成器（核心）

| 功能 | 说明 |
|------|------|
| 检索结果 → 上下文 | 拼接 Top-K 检索结果为 LLM 可读的上下文块 |
| Prompt 模板 | 国航业务支持助手 System Prompt + 上下文注入 |
| LLM 调用 | 用 DeepSeek/通义千问 生成回答 |
| 引用提取 | 从回答中解析 `[来源: ...]` 标记，生成 Citation 列表 |
| 流式输出 | yield 逐 token，支持 SSE |
| 上下文窗口管理 | Token 超限时按「优先保留高分段 + 条款完整性」截断 |
| 兜底策略 | 检索结果置信度低 → 标注「建议查阅原文」 |

### 2. `rag/callbacks.py` —— LangSmith 回调

- 检索耗时标记
- LLM 调用 token 统计
- 全链路 trace_id 传递

## Prompt 设计要点

### System Prompt

```
角色：国航内部业务支持助手
语气：专业、准确、简洁
格式：结论先行 → 政策依据(条款编号) → 操作指引
红线：不确定时必须标注「以下信息可能需要进一步核实，建议查阅原文」
引用：每个结论标注 [来源: 文档名 条款编号]
```

### Few-shot 示例

```
问：经济舱旅客能免费托运多少行李？
答：国内航线经济舱旅客可免费托运 20kg 行李，限 1 件，单件不超过 32kg。
[来源: 托运行李运输规定 第1条]
具体标准如下：
| 服务等级 | 重量限制 | 件数限制 |
|---------|---------|---------|
| 头等舱 | 40kg | 3件 |
| 经济舱 | 20kg | 1件 |
如有特殊行李（运动器材、乐器等），请参考第4条特殊行李规定。
[来源: 托运行李运输规定 第4条]
```

---

## 差异化亮点

- **条款级引用**：不是「来自文档A」，而是「行李运输规定 第3.2条」
- **不确定声明**：置信度低时主动标黄
- **上下文窗口管理**：对话过长时智能截断，保留条款完整性
- **流式输出**：SSE 逐 token 推送，首 token 延迟 < 1s
